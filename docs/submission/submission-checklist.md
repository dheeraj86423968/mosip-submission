# Submission checklist

Maps every artefact in the MOSIP Decode 2026 submission guidelines to a
path in this repository or to the external location where it must be
placed. Mandatory items are marked with an asterisk as in the guidelines.
The "Status" column must be updated before the submission email is sent;
the judging weights are Functionality 40 %, Quality of deliverable 40 %,
UX 10 %, Presentation 10 %.

## Submission process (from the guidelines)

1. Source code: this repository (public or shared with MOSIP).
2. Other deliverables (deck PDF, video, student IDs, any evaluation report
   that contains corpus details): cloud folder with view access for
   `decode@mosip.io`.
3. Email to `decode@mosip.io` with team name, "Problem Statement 04 —
   Face Liveness Detection and Presentation Attack Detection", repository
   URL and cloud folder URL.
4. Verify every link opens in a private browser window before sending.

## Pre-submission verification

- [ ] `mvn -B -ntp verify` green on a clean clone with JDK 17.
- [ ] CI green on `main` (build, formal, iso-report skipped or green).
- [ ] Root README status table reflects the actual state of every module.
- [ ] No frames, videos or images of real people in the repository
      (`git ls-files | grep -Ei '\.(mp4|avi|mov|jpg|jpeg|png|webp|heic)$'` reviewed;
      the only expected hits are the vector-drawn mockup renders in `docs/ux/png/`).
- [ ] `docs/corpus/` is tracked (the root `.gitignore` rule `corpus/` also matches
      `docs/corpus/`; it needs a `!docs/corpus/` exception) and contains only the blank templates.
- [ ] Any ISO report quoted is labelled as a self-evaluation and follows
      `docs/corpus-ethics.md` §12.
- [ ] No research-only dataset material in the repository.
- [ ] `docs/testing/results-<date>.md` filled for the submitted commit.
- [ ] Deck and video match the status table (no claim beyond it).
